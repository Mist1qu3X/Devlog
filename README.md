# Блог-платформа

Учебный монолитный веб-проект по дисциплине «Создание программного обеспечения»
(практические занятия №2–№4). Пользователи регистрируются, публикуют посты с
тегами, лайкают и комментируют их. Есть роли (пользователь / администратор) и
панель администратора со статистикой.

**Стек:** React (Vite) + FastAPI (Python) + PostgreSQL.

## Возможности

- Регистрация и вход (JWT, пароли хешируются bcrypt), роли `user` / `admin`
- Лента постов: поиск по заголовку, фильтр по тегам (топ-5 популярных + поиск), сортировка (новые / популярные)
- CRUD постов с тегами; комментарии; **лайки** постов
- Публичные профили со статистикой; смена имени и **загрузка аватара**
- **Панель администратора**: метрики, графики, управление пользователями, модерация
- Светлая и тёмная темы, иконки (Font Awesome), шрифт Inter, анимации, тосты

## Требования

- Python 3.10+
- Node.js 18+
- PostgreSQL 13+ (запущен на localhost:5432)

## Запуск backend

```bash
cd backend
python -m venv venv
venv\Scripts\activate            # Windows (Linux/Mac: source venv/bin/activate)
pip install -r requirements.txt
```

Настроить `.env` (уже создан; при необходимости поправить пароль от PostgreSQL):

```
DB_HOST=localhost
DB_PORT=5432
DB_NAME=blog_db
DB_USER=postgres
DB_PASSWORD=ваш_пароль
SECRET_KEY=любая_длинная_случайная_строка
```

Создать базу, наполнить данными и запустить сервер:

```bash
python create_db.py     # создаёт базу blog_db
python seed.py          # демо-данные (админ, пользователи, посты, лайки)
# если база уже была создана в старой версии — вместо seed примените:
# python migrate.py     # добавит роль, таблицу лайков и аккаунт админа
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

- API: http://localhost:8000
- Swagger-документация: http://localhost:8000/docs

## Запуск frontend

```bash
cd frontend
npm install
npm run dev -- --host 0.0.0.0
```

На компьютере открыть http://localhost:5173. Vite проксирует API-запросы на backend на порту `8000`. Чтобы открыть сайт на телефоне или другом устройстве в той же Wi-Fi сети:

1. Узнать локальный IP компьютера (macOS: `ipconfig getifaddr en0`; Windows: `ipconfig`; Linux: `hostname -I`).
2. На втором устройстве открыть `http://<локальный-IP-компьютера>:5173`, например `http://192.168.1.25:5173`.
3. Если соединение блокируется, разрешить входящие подключения для портов `5173` и `8000` в брандмауэре компьютера.

`localhost` на телефоне указывает на сам телефон, поэтому используйте IP компьютера. API-запросы проходят через dev-сервер фронтенда; backend отдельно слушает порт `8000`.
Пользователи и переписки хранятся в одной PostgreSQL-БД `blog_db`. Таблицы `conversations` и `chat_messages` создаются backend при запуске; в pgAdmin нажмите Refresh у `blog_db → Schemas → public → Tables`, чтобы увидеть их.

## Деплой в Dokploy

В корне репозитория находится `compose.yaml`: он собирает FastAPI backend и React frontend. Внешний домен нужно направить на сервис `frontend`, порт `80`; API остаётся внутренним и проксируется Nginx по `/api/`. Backend при старте создаёт недостающие таблицы, поэтому пользователь БД должен иметь права на создание/изменение таблиц.

1. В Dokploy создайте приложение типа **Compose** из Git-репозитория и выберите ветку `main`.
2. Добавьте переменные окружения приложения в настройках Dokploy:
   - `DATABASE_URL` — полная строка PostgreSQL-подключения к БД, доступной из сети контейнеров приложения.
   - `SECRET_KEY` — длинный случайный секрет для подписи JWT.
3. Разверните приложение и назначьте домен сервису `frontend` на порт `80` с HTTPS. Backend-порт `8000` наружу публиковать не нужно.
4. Проверка доступности frontend: `/healthz`; проверка API: `/api/health`.

Не добавляйте реальные `.env`-файлы, строки подключения, JWT-секреты или дампы БД в Git. Перед деплоем смените пароль базы данных, если он когда-либо передавался в чате или другом публичном месте; новый пароль укажите только в переменной `DATABASE_URL` в Dokploy. Если указанный хост БД не резолвится из контейнера backend, подключите приложение к той же Docker-сети, что и PostgreSQL, либо используйте доступный из Dokploy адрес БД.
Если устройства не соединяются, проверьте, что они в одной локальной сети, разрешены входящие порты `5173` и `8000`, а VPN или настройка изоляции клиентов Wi-Fi не блокирует соединение. Доступ рассчитан на доверенную локальную сеть, не на публикацию серверов в интернете.

## Личные чаты и комментарии

- Количество комментариев в ленте можно нажать, чтобы перейти к комментариям поста.
- Авторизованные пользователи могут начать личный чат с профиля другого пользователя или через раздел «Чаты». Сообщения обновляются автоматически.
- В чатах можно отправлять эмодзи и фото (изображения автоматически сжимаются; лимит после сжатия — 5 МБ), сообщения хранятся в `blog_db`.
